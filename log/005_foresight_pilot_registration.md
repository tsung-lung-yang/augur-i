## 2. 預見設計（試跑涉及的部分）

試跑條件：T0、T3-TR、T3-TT、T3-R、T5-TR（LOG-001 第 6 節），**另加 T5-TT**（本紀錄新增，2026-11-11 10:47 決定，當時沒有任何 T0 以外的結果）。理由：(1) 試跑成為完整的「目標 × 模式」2×2（T3、T5 × TR、TT），能初步檢查推論時想像的價值是否因目標而不同；(2) T0、T3-TT、T5-TT 三個模型是 AUGUR-II 止損實驗 S-1（逐狀態互補性）離線版的前提。**LOG-001 第 6 節的試跑判定規則不變**：仍只看 T3-TR 對 T3-R、T3-TR 對 T0；T5-TT 只記錄，不影響去留。代價約 1.3 天 GPU。T2（DINO）、T4（潛在運動）只在主矩陣出現，其設計在試跑判定後、主矩陣前另行登記。

| 項目 | 設定 |
|---|---|
| 預見 token 數 K | **4**，對應主相機畫面的 2×2 四個象限 |
| 預測時距 | **1 秒**：LIBERO 10 fps → +10 幀；SSv2 抽成 2 fps → +2 幀。真正的未來超出 episode／影片結尾的樣本，不計預見損失（遮罩） |
| 位置 | K 個可學習查詢 token 接在 VLM 前綴最後（狀態 token 之後）；查詢可看影像、語言、狀態；前綴其他 token 看不到查詢；動作專家在每一層都被遮住、看不到查詢 |
| -TR 模式 | 查詢輸出經預測頭（Linear 960→1024、GELU、Linear 1024→d）得到 ẑ，只用來算預見損失。動作 token 的位置編號照「沒有查詢」的方式排，因此同一組權重下 -TR 模型的動作與無預見模型完全相同（`test_foresight.py` 測試 1：改動查詢，動作差 0.00） |
| -TT 模式 | ẑ 經線性投影加位置嵌入成為 K 個條件 token，放在動作專家的動作 token 前面；動作生成時看得到自己想像的未來。訓練用模型自己的 ẑ（不用真實未來），訓練與推論一致。訓練時每步多跑一次前綴 |
| T3 目標（JEPA 潛在） | 未來主相機畫面 → 凍結的 SigLIP＋connector（快取）→ VLM 16 層語言層（用 LoRA 的 EMA 權重，τ = 0.996）→ 每個象限取平均 → LayerNorm。d = 960 |
| T5 目標（低解析光流） | RAFT-small（torchvision 預設權重）算「現在 → 1 秒後」的光流，平均池化到 8×8，除以影像邊長，每個象限 4×4×2 = 32 維。**各資料來源用自己的平均和標準差標準化**（見第 5 節） |
| 損失 | 預見損失 = ẑ 與目標的 MSE（有效樣本平均）；微調時總損失 = 動作損失 + λ × 預見損失，**λ = 0.1** |
| 預見誤差（報告用） | ẑ 與目標的餘弦距離，K 個 token 平均 |
| 可訓練參數 | LoRA（同 LOG-004）＋查詢 3,840＋預測頭；TT 另加條件投影。T3 共 3,610,304、T5 共 2,659,104（不含動作專家） |
| 存檔 | 主模型照 LOG-004 合併 LoRA，仍是一般 SmolVLA；預見模組另存 `augur.safetensors`，線上與 EMA LoRA 另存 `augur_lora.safetensors`；評測時 `eval_mixed.py` 依 `augur_train.json` 自動裝上預見模組（`test_finetune_foresight.py`：重新載入後動作差 ≤ 0.011，屬 bf16 捨入；TT 未載入預見權重時動作差 0.11） |

## 3. 預見預訓練

| 項目 | 設定 |
|---|---|
| 程式 | `scripts/pretrain_foresight.py` |

| 優化 | AdamW，lr 1e-4，betas (0.9, 0.95)，weight decay 1e-10，warmup 500 步，餘弦衰減到 2.5e-6，梯度裁切 10，bf16 |

| 運算公平（選項 a） | 所有條件的微調步數同為 S；預訓練是處理本身，GPU 時數照實報告 |

## 5. 目標快取

- `scripts/foresight_cache.py`：LIBERO 273,465 幀與 SSv2 子集的全部幀。
- 影像嵌入：凍結 SigLIP＋connector 的輸出（64 × 960，float16），所有條件共用（視覺編碼器凍結、沒有 LoRA）。

- **相對計畫的更動：光流按來源分別標準化**。冒煙測試中，用兩來源合併的統計時，SSv2 的 T5 損失是 LIBERO 的約 9 倍（人類影片常有鏡頭晃動），預訓練會被人類影片主導，微調時 LIBERO 的目標尺度也會偏小。改為各來源用自己的平均與標準差；模組保留 LIBERO 的統計供微調使用。此更動在任何正式訓練之前決定，依據只是損失尺度，不是任何下游結果。

## 9. 評測時間重估

- 實測（LOG-003）：擾動下每回合約 30–36 秒（多數失敗、跑滿步數）。
- 試跑每個 checkpoint：LIBERO-Plus 開發切分 420 回合＋LIBERO-PRO 60 回合 ≈ 4.4 小時；試跑共 12 個 checkpoint（6 個條件 × 2 個 seed）≈ 53 小時。
- 原版 LIBERO 開發切分（T0 曲線，每個 checkpoint 120 回合）：單獨執行時每個 checkpoint 約 20–26 分鐘。
- 主矩陣每個 checkpoint：LIBERO-Plus 保留切分 588 回合＋LIBERO-PRO 84 回合 ≈ 6.2 小時。13 個條件 × 3 個 seed 即約 240 小時評測，單張 GPU 在 12-04 截止前**做不完**。
- 處理：主矩陣的範圍（條件、seed 數、每格回合數）在試跑判定之後、主矩陣開始之前另行登記，**只依剩餘時間預算決定，不看試跑以外的任何結果**；延伸摘要以試跑加上可完成的主矩陣部分為準。

## 11. 執行方式

- `scripts/make_pilot_queue.py --S <S> --t5_tt` 產生試跑佇列，`scripts/run_queue.py` 依序執行、可中斷續跑、失敗即停。**一次只執行一個工作**（見第 13 節）。順序：等 T0 曲線評測結束 → T0 seed 0 在試跑清單上的評測與地板關卡（未通過即停）→ 快取 → 冒煙（100 步 T3-TT 微調＋8 回合評測）→ 預訓練計時 → 依規則自動決定 P（`set_P`）→ 3 個預訓練 → seed 0 的 5 個預見條件（每個訓練後立即評測）→ seed 1 的 6 個條件。
- 評測批次：LIBERO-Plus 與 LIBERO-PRO 皆為 8（記憶體限制）。
- 試跑判定規則照 LOG-001 第 6 節，不在此更動。
